Build on a good idea.

01

Make the website your own

Choose a concept and change the pages, styling, content, and features to fit it. This could become a study planner, a reading tracker, a small inventory, or something else you can explain. Meaningful changes matter more than changing a few colors.

02

Turn recovery into a Stack feature

The starter recovery buffer deliberately handles the oldest removed item first. Your goal is LIFO: the most recently removed item must return first.

The designated file is backend/stack.py. Its HistoryBuffer class is called by the real Flask routes. Replace the current dictionary-based buffer with your own Stack implementation, keeping its public methods usable by the website.

  • Implement push, pop, peek, is_empty, and size.
  • Keep to_list() in bottom-to-top order so SQLite can save and reload it.
  • Handle an empty Stack safely.
  • Use a Stack representation with efficient operations at the top.

THE BEHAVIOR TO DEMONSTRATE

Remove A, then B, then C.

Restoring must bring back C, then B, then A. Reading the next item with peek() must leave the Stack unchanged.

Refresh the page between operations. The database and the website should still agree.

03

Check it, then explain it

Run CHECK_STACK.bat on Windows, or python challenge/check_stack.py. The untouched starter intentionally fails the LIFO checks. Your completed solution should pass them.

Run RUN_TESTS.bat to check the rest of the website. Submit your source code, a short setup guide, and evidence of your modifications. Each member should be able to explain their own contribution.

Find your part of the full-stack project

One project, three clear areas. Start with the folder that matches what you want to change.

FRONTEND
frontend/templates/ contains the HTML/Jinja pages. frontend/static/style.css controls the look and layout.
BACKEND
backend/app.py handles browser requests and input checks. backend/stack.py is your required Stack challenge.
DATABASE
database/db.py contains SQLite helpers and SQL queries. database/schema.sql defines the tables. Saved records go in database/data/workbench.sqlite3.
TESTS
tests/ checks the working website. challenge/check_stack.py checks the LIFO goal separately.
GUIDES
docs/REPOSITORY_MAP.md maps each file to its job. Each main folder also has its own README.md.

Flow: browser form → backend route → Python logic and SQLite → rendered HTML response. Launch from the project root with START_WEBSITE.bat.

Read docs/STUDENT_ACTIVITY.md for the full submission checklist.
